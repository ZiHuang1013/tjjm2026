## 组员如何更新

1. 先同步最新`main`，从它建立本次任务分支（例如`data/update-20261013`）。已有个人分支须先合入最新`main`，才能看到本数据目录。
2. 保留列名、列顺序、单位、UTF-8编码和日期升序；以`target_date`为唯一键。当天截止前未知的y留空，等真实结算值公布后再补。输入只用截止前可得信息，并记录实际获取时间；当日截止后新公告不得倒填成当时输入。
3. 增补或更正主表时，同步更新受影响的逐行追溯、目标审计、覆盖情况以及说明。每个目标日应有18条输入追溯，值应与主表一致；缺失也保留追溯记录。原始证据保存在团队约定位置，记录文件哈希和定位。
4. 在[更新记录](./更新记录.md)登记数据日期、来源、实际获取时刻（含时区）、新增/更正范围、原因和未确认事项。不要把临时猜测值写入正式主表；不要覆盖旧证据而不记录变化。
5. 发起PR，由另一名组员核对来源、截止边界、单位、日期唯一性和变更范围后合并。数据变化后重新生成覆盖统计和manifest哈希，并记录本次实际完成的检查。旧核验JSON作为历史证据保留，不改成新的“passed”结果。

这是建议的团队操作流程。当前没有配置自动检查或强制分支保护，也没有自动每日更新任务；上传本身不会自动抓取新数据。
